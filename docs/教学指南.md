# 青禾集市（c2c）教学指南

> 版本：2026-10-29 · 适用对象：想用本项目学习 Java Web 全栈开发的同学
> 配套文档：README.md（功能/部署）、COMMON.md（公共组件）、docs/项目分析与优化建议.md（已知问题清单）
> 学习主线建议：**先跑起来 → 跟着一次请求走完全链路 → 分模块精读 → 动手改**。不要从第一行代码顺序读。

## 2. 环境搭建（30 分钟 checklist）

按 README「快速开始」执行，以下为易踩的坑（均来自真实排障记录）：

1. **JDK 8 与 Maven**：`mvn -v` 确认是 1.8。项目锁定 Java 8 / Spring Boot 2.7，不要用 JDK 17 直接跑。
2. **数据库**：`mysql -uroot -p c2c < sql/init.sql` 再 `... < sql/data.sql`。注意 `init.sql` 会**清空重建** c2c 库，本地有数据先备份。
3. **Redis**：必须可用。验证码、token 黑名单、AI 缓存全在 Redis。
4. **配置文件**：`cp config/application.example.yml config/application-pro.yml`，填数据库/Redis/JWT 密钥。JWT 密钥随便 ≥32 字节的随机字符串即可（本地）。
5. **logs 目录**：Spring Boot 不会自动创建日志父目录，先在项目根 `mkdir logs` 再启动，否则「启动成功但看不到日志文件」。
6. **默认 profile**：当前仓库代码默认 `prod`，本地开发建议启动时显式 `--spring.profiles.active=test`，或把外部配置命名为 `application-test.yml` 放 config/ 下。
7. **验证启动**：`mvn clean package -DskipTests` → `java -jar target/c2c-monolith.jar` → 访问 `http://localhost:8080/api/v1/swagger-ui/index.html`。
8. **前端**：`cd frontend && npm install && npm run dev`（用户端 5173）；`cd admin-frontend && npm install && npm run dev`（管理端 5174）。
9. **演示登录**：手机号验证码登录（test 环境验证码回显在响应里，方便联调）；所有演示账号（含管理端 admin）统一密码 `ww123456`（见 sql/data.sql 头部注释）。

## 3. 项目心智地图

### 3.1 一次请求的完整旅程（以「登录后发布商品」为例）

```
浏览器 (Vue)
  │  POST /api/v1/product/publish  Header: Authorization: Bearer <token>
  ▼
Nginx (生产) / Vite dev-server (本地开发，代理 /api → 8080)
  ▼
AuthTokenFilter        ← ① 验 JWT 签名/过期/黑名单 → ② 通过则包一层 request，
                            让 Controller 用 @RequestHeader("X-User-Id") 拿到用户 ID
  ▼
RequestLogFilter       ← 记日志（在过滤器链最外层）
  ▼
ProductController      ← ③ 参数校验 (@Valid) → 调 Service
  ▼
ProductServiceImpl     ← ④ 业务逻辑（此处@Transactional 开事务）→ MyBatis-Plus Mapper
  ▼
MySQL / Redis
  ▼
统一返回 R{code,message,data} → 前端 axios 拦截器解包 → ElMessage 报错或渲染
```

读代码时抓住三条主线：**数据怎么进来（Controller/DTO）→ 规则怎么执行（Service/状态机）→ 数据怎么落地（Mapper/Redis）**。

### 3.2 模块地图（后端 `src/main/java/com/c2c/`）

| 包 | 职责 | 精读价值 |
|---|---|---|
| `common/` | 过滤器、统一响应、异常、JWT、常量、枚举、启动校验 | ⭐⭐⭐ 一切的地基，最先读 |
| `user/` | 登录/注册/验证码/微信登录/地址 | ⭐⭐⭐ Redis 用法最密集 |
| `product/` | 商品 CRUD、分类、评论、意向、上传 | ⭐⭐⭐ 业务最典型 |
| `order/` | 下单/支付/发货/收货/取消 | ⭐⭐⭐ 状态机+事务+锁，论文级素材 |
| `wallet/` | 余额/充值/退款/流水 | ⭐⭐⭐ 资金安全：原子扣减必看 |
| `im/` | 会话/消息/未读 | ⭐⭐ 会话归一化设计巧妙 |
| `rating/` `favorite/` | 评价/收藏 | ⭐⭐ |
| `review/` | 举报/申诉/昵称审核/操作日志 | ⭐⭐ 审核流+审计日志 |
| `admin/` | 管理端认证/统计/角色 | ⭐⭐⭐ 三级权限体系 |
| `ai/` | AI 智能发布（大模型+规则引擎降级） | ⭐⭐⭐ 创新点 |
| `eco/` `banner/` `announcement/` | 低碳统计/轮播/公告 | ⭐ 聚合 SQL 案例 |

前端对应：`frontend/src/api/`（接口封装）、`views/`（24 个页面一一对应后端模块）、`admin-frontend/src/views/`（10 个管理页）。

## 4. 精读路线（建议按顺序，每主题含「读什么 + 思考题」）

### 主题 1：启动与配置（0.5 天）

- 读：`C2cMonolithApplication.java`（`@MapperScan`）、`application.yml`、`config/application.example.yml`、`JwtSecretCheckEnvironmentPostProcessor`、`WebMvcConfig`、`MyBatisPlusConfig`（分页插件）。
- 要点：多 profile 机制；外部 config 目录如何逐 key 覆盖 jar 内配置；为什么 JWT 弱密钥要拒绝启动。
- 思考题：如果把 jar 拷到别的目录启动，日志和上传目录会去哪？（答案在 README「日志」一节）

### 主题 2：统一响应与异常（0.5 天）

- 读：`common/result/R.java`、`common/exception/{BusinessException, GlobalExceptionHandler}.java`。
- 要点：业务异常直接抛，全局兜底不泄露堆栈；`@Valid` 校验失败如何转成可读中文提示。
- 动手：给 `ProductCreateDTO.price` 加 `@DecimalMin("0.01")`，发负数价格看返回什么。

### 主题 3：认证与授权（1~2 天，核心）

- 读：`common/utils/JwtUtils.java`、`common/filter/AuthTokenFilter.java`、`user/service/impl/UserServiceImpl.java`（登录部分）、`admin/controller/AdminAuthController.java`、`common/constant/AdminPerm.java`。
- 要点：JWT 三段结构（Header/Payload/Signature）与 HS256；过滤器为什么用 `HttpServletRequestWrapper` 改写请求头；白名单/只读 GET 清单的设计；三级权限（总管理员/次级管理员/审核员）如何在**一个过滤器**里完成。
- 思考题：为什么权限校验放在过滤器而不是 @PreAuthorize？各有什么利弊？
- ⚠️ 已知问题：读的时候对照《项目分析与优化建议.md》S2~S5，能看懂「哪里还能被绕过」比看懂实现更重要。

### 主题 4：数据访问层（1 天）

- 读：任选 `ProductMapper.java` + `ProductServiceImpl.java` 全文。
- 要点：`BaseMapper` 提供的 CRUD；`LambdaQueryWrapper` 类型安全查询；`Page` 物理分页（依赖 M3 的分页插件）；`init.sql` 里的索引设计（对照 2.3 节，看哪些查询命中哪个索引）。
- 动手：用 `EXPLAIN` 分析 `MATCH(title, description) AGAINST(...)` 搜索与 `LIKE '%关键词%'` 的差别（全文索引最小词长默认 2~4，搜单字可能无结果）。

### 主题 5：事务与资金安全（1~2 天，核心）

- 读：`wallet/service/WalletService.java`、`order/service/impl/OrderServiceImpl.java`、`user/mapper/UserMapper.java`（`deductBalance` 原子 SQL）。
- 要点：`@Transactional` 边界；为什么扣款必须 `UPDATE ... SET balance=balance-? WHERE id=? AND balance>=?` 而不是「查出来减了写回去」；订单状态机每个迁移的守卫条件；`synchronized` + `ConcurrentHashMap` 锁在单体内的局限。
- 思考题：两个用户同时买同一件商品，哪一层保证不会超卖？

### 主题 6：缓存与性能（1 天）

- 读：`ProductServiceImpl.java`（列表/详情缓存、热度）、`UserServiceImpl.java`（验证码、限频、登录锁）、`ai/service/AiServiceImpl.java`（按图缓存）。
- 要点：缓存 key 设计规范（`sms:code:{account}`、`ai:publish:{md5}`）；缓存与数据库一致性取舍；哪些数据**不应该**缓存（余额）。
- 动手：发两次同图 AI 识别，第二次是否走缓存（看日志/Redis）。

### 主题 7：IM 与未读数（0.5~1 天）

- 读：`im/service/ImService.java`、`im/controller/ImController.java`、前端 `ChatView.vue` 轮询逻辑。
- 要点：会话按「小 ID 在前」归一化避免 A-B/B-A 重复会话；未读数双写（conversation 冗余 + message.is_read）的便利与隐患。

### 主题 8：前端工程（2 天）

- 读：`frontend/src/api/request.js`（拦截器：token 注入/401 跳登录/GET 弱网重试）、`router/`（路由守卫）、`stores/`（Pinia）、`App.vue`（全局 uiverse 样式）、一个完整页面如 `ProductPublishView.vue`。
- 要点：为什么 GET 失败可以重试而 POST 不行；`keep-alive + onActivated` 的刷新模式；`router-view :key="route.fullPath"` 解决的路由复用坑（BUGS.md 有记录）。
- 动手：给管理端某个列表页加加载骨架屏（参考 `SkeletonCard.vue`）。

### 主题 9：AI 与低碳模块（0.5~1 天，创新点精读）

- 读：`ai/` 全部、`eco/service/EcoServiceImpl.java`。
- 要点：**可配置接入 + 失败降级**模式（外部依赖不可用时系统仍可用，这个思想可复用到任何第三方对接）；历史成交均价修正估价的融合思路；聚合统计 SQL（LEFT JOIN 补默认系数）。

### 主题 10：部署（0.5 天）

- 读：`deploy/` 下 `start-backend.sh`、两个 nginx 示例配置、`.gitignore`。
- 要点：启动脚本里的三道防线（JDK 检查、JWT 密钥检查、日志目录创建）；Nginx 如何同时托管前端静态文件与反向代理 /api；哪些文件绝不能进 git。

## 5. 动手练习（由浅入深，全部可在真实代码上完成）

**入门（照猫画虎）**
1. 新增一个「商品标签」只读接口：从 `category` 表查全部二级分类，30 行内完成（仿 `CategoryController`）。
2. 给钱包流水接口加按类型筛选参数。
3. 前端商品卡片加「收藏数」角标。

**进阶（理解机制）**
4. 实现「登录失败 3 次出现图形验证码」——需要动 Redis、登录接口、前端 LoginView。
5. 给订单加「延长收货」：买家点一次 +3 天，只允许一次（涉及状态机守卫 + 新字段 + 前端按钮）。
6. 用 Spring 的 `@Scheduled` 实现「30 分钟未支付订单自动取消」（参考优化路线 M2.4）。

**挑战（综合）**
7. 把 IM 轮询改成 SSE（Server-Sent Events）推送，失败自动回退轮询。
8. 给 AI 估价加「同成色加权」：历史均价只统计同 condition 的已售商品。
9. 设计并实现「评价标签」前端多选 + 后端存储（tags 字段已存在，是 json 类型）。

> 练习完成标准：功能可用 + `mvn package` / `npm run build` 通过 + 能在 Swagger/页面上演示。

## 6. 常见坑 FAQ（读代码前必看）

| 现象 | 原因 | 出处 |
|---|---|---|
| 部署后没有日志文件 | Logback 不自动建目录 + 相对路径依赖 cwd | BUGS.md、README「日志」 |
| 切换商品详情页数据不刷新 | Vue Router 复用组件，`onMounted` 不再触发 | BUGS.md（`:key="route.fullPath"` 修复） |
| 搜索单个字没结果 | MySQL FULLTEXT 默认最小词长 | 主题 4 动手 |
| 启动报 JWT 密钥错误 | 启动校验拦截弱密钥，属有意设计 | `JwtSecretCheckEnvironmentPostProcessor` |
| 本地日志中文乱码 | Windows 控制台 GBK | `application.yml` 已显式 UTF-8 |
| 生产验证码出现在响应里 | `sms-echo-code` 默认值问题（已知安全项 S1） | 项目分析与优化建议.md |
| 小程序真机请求失败 | 未配置合法域名/HTTPS | weapp/README、优化路线 M5 |

## 7. 学习成果自测

能不看代码回答以下问题，说明已掌握：

1. 前端请求如何携带身份？后端哪个组件、按什么顺序校验？
2. 为什么余额扣减用条件 UPDATE 而不是读-改-写？并发下会发生什么？
3. 订单从下单到完成经过哪些状态？每个状态允许哪些操作、拒绝哪些？
4. 会话表为什么存 `user1_id/user2_id` 且约定小 ID 在前？
5. AI 模块在没有 API Key 时如何保证功能仍可用？
6. 三级权限体系里，次级管理员想访问 `/admin/orders` 要经过哪些校验？
7. 配置里的敏感信息为什么不会泄露到 git？哪些机制共同保证？
