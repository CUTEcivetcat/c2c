# G6 优惠券抢购 实施方案（owner 实施指南）

> 状态：**✅ 后端全链路 + 管理端控制台 + 用户端页面完成（2026-11-13，81/81 测试绿）**；管理端券接口曾在 8081 临时实例冒烟通过。
> 本轮范围：券模板/发放、用户领券（并发防超发/防重复）、下单选券抵扣、支付按抵扣后金额扣款、管理端发券接口、管理后台券管理页；收尾补券过期定时扫描、已支付取消释放券、我的券包/结算选券/首页与详情页活动栏直接领取；券绑定适用分类（0 全部分类通用），试算按商品分类校验。
> 券类型：**满减券（type=1）+ 折扣券（type=2）**；折扣率存于 `discountAmount`（0~1，如 0.9 表示 9 折）。

---

## 1. 目标与业务口径

| 环节 | 规则 |
|---|---|
| 建券 | 管理员创建券批次：类型、面额/折扣率、使用门槛、发行总量、有效期、启停 |
| 领券 | 生效中、在有效期内、有库存方可领；同一用户同一张券限领一张 |
| 并发抢券 | 库存走模板表原子条件更新，防超发；唯一索引防重复领取 |
| 用券 | 下单时选择用户券，校验归属/状态/有效期/门槛/适用分类，计算抵扣额并落单 |
| 支付 | 先锁定券（原子置已使用、回填订单），再按抵扣后金额扣余额进托管 |
| 退券 | 未支付订单取消/超时：券未锁定，无需退回；已支付订单取消：券未过期则退回未使用并解绑订单，已过期置过期 |

**抵扣试算规则**：订单金额 = 商品价 + 运费；满足门槛（`orderAmount >= minAmount`）后：
- **满减（type=1）**：抵扣 `discountAmount`（领取快照减免额）；
- **折扣（type=2）**：抵扣 `orderAmount × (1 − 折扣率)`，四舍五入保留两位；
- 抵扣额不超过订单金额；应付 = 订单金额 − 抵扣额（不为负）。
- **适用分类**：券 `categoryId=0` 为全部分类通用；绑定分类的券仅可用于同分类商品，试算/下单时按商品分类校验，不符抛"该券不适用于此分类商品"。

## 2. 数据模型

迁移脚本：`sql/sqlgx/2026-11-12_0500.sql`（券模板/用户券/订单抵扣字段）、`2026-11-12_0600.sql`（券适用分类 `category_id`）；全量脚本 `sql/init.sql` 已同步。

### 2.1 `coupon_template` 券模板（发行批次）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 模板 ID |
| name | VARCHAR(100) | 券名称 |
| type | TINYINT | 券类型：1 满减 2 折扣 |
| discount_amount | DECIMAL(10,2) | 满减：减免金额；折扣：折扣率（0~1，0.9=9 折） |
| max_discount_amount | DECIMAL(10,2) | 折扣券独立封顶减免额，0 不封顶；仅作用于折扣券，满减券不使用 |
| min_amount | DECIMAL(10,2) | 使用门槛，0 为无门槛 |
| category_id | BIGINT | 适用分类 ID（category.id），0 全部分类通用；匹配时沿分类 parentId 祖先链上溯，父类券可用于子类商品 |
| total_count | INT | 发行总量 |
| claimed_count | INT | 已领取数（原子自增） |
| valid_start / valid_end | DATETIME | 有效期起止，空为不限 |
| status | TINYINT | 1 生效 / 0 停用 |

### 2.2 `user_coupon` 用户已领券

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 用户券 ID（订单 `coupon_id` 回填此 ID） |
| coupon_id | BIGINT | 券模板 ID |
| user_id | BIGINT | 持有人 |
| status | TINYINT | 0 未使用 / 1 已使用 / 2 已过期 / 3 已作废 / 4 已锁定（待支付占用） |
| order_id | BIGINT | 使用后回填订单 ID |
| discount_amount | DECIMAL(10,2) | 抵扣金额快照 |
| receive_time / use_time / expire_time | DATETIME | 领取/使用/过期时间 |

唯一索引 `uk_coupon_user(coupon_id, user_id)` 防重复领取；普通索引 `idx_user_status(user_id, status)`。

### 2.3 `order` 新增字段

`coupon_id`（使用的用户券 ID，未用券为 NULL）、`discount_amount`（抵扣金额快照，默认 0）。`total_amount` 存**抵扣后应付金额**。

- `PUT /order/{id}/pay`：有券先锁定再扣款（口径见 §4.2）。

## 4. 关键并发与事务口径

### 4.1 领券防超发/防重复

`CouponTemplateMapper#claimOne` 原子条件更新：

```sql
UPDATE coupon_template SET claimed_count = claimed_count + 1
WHERE id = #{id} AND claimed_count < total_count AND status = 1
```

- 受影响行数 0 → 已抢光或已停用，拒绝；
- 重复领取先按 `(coupon_id,user_id)` 查询拦截，并发兜底由唯一索引保证（撞键回滚库存计数）；
- 服务层另加分片锁降低同券并发冲突，DB 原子更新为最终兜底。

### 4.2 支付锁定券

`CouponService#markUsed` 原子条件更新：

```sql
UPDATE user_coupon SET status=1, order_id=#{orderId}, use_time=NOW()
WHERE id=#{id} AND status=0
```

- 行数 0 → 券已被其他订单占用，抛异常，整单事务回滚、不扣款；
- `OrderServiceImpl.pay()` 先 `markUsed` 成功，再 `walletService.deductBalance` 按 `totalAmount`（抵扣后）扣款。

### 4.3 状态与退款

- 下单不锁定券；支付成功才置已使用并回填订单；
- 未支付订单取消/超时关单：券仍为未使用，无需退回；
- 已支付订单取消：按托管金额全额退款，`CouponService#releaseAfterCancel` 把绑定本订单的已使用券退回未使用（未过期）或置过期（已过期），解绑订单与使用时间；仅处理状态为已使用且订单号匹配的券，避免误退他单券。

### 4.4 过期扫描

`coupon/task/CouponExpireTask` 每 10 分钟全量扫描：`status=0` 且 `expire_time < now` 的未使用券批量置为过期；用户进入「我的券」列表时另有按用户惰性过期兜底。
