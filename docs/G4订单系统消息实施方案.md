## 1. 目标

订单状态流转时，给买家和卖家双方的私信会话各发一条**系统通知**（messageType=4，聊天页居中灰条展示）：

| 事件 | 触发点 | 文案（建议） |
|---|---|---|
| 已支付 | `OrderServiceImpl.pay()` 成功后 | `订单已支付，等待卖家发货 #订单号` |
| 已发货 | `OrderServiceImpl.ship()` 成功后 | `卖家已发货（{快递公司} {单号}），请注意查收` |
| 已完成 | `OrderServiceImpl.receive()` 成功后 | `订单已完成，感谢交易 🎉` |
| 已取消 | `OrderServiceImpl.cancel()` 成功后 | `订单已取消：{取消原因}` |
| 超时取消 | `OrderTimeoutTask.cancelTimeoutOrders()` | `超时未支付，订单已自动取消` |

## 2. 为什么几乎不用写前端

- **聊天页**：`ChatView.vue` 已渲染 `messageType === 4` 为居中灰条（第 18-19 行），零改动；
- **会话列表**：`lastMessage` 自动显示通知文案（ImService.sendMessage 会更新会话最后消息与未读数）；
- **审核模块**早已用同一套机制（`ReviewServiceImpl#notifyUser`），照抄范式即可。

## 3. 实施步骤（三步）

### 步骤 1：新建通知组件 `src/main/java/com/c2c/order/service/OrderNoticeService.java`

```java
package com.c2c.order.service;

import com.c2c.im.entity.Conversation;
import com.c2c.im.service.ImService;
import com.c2c.order.entity.Order;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

/**
 * 订单事件系统通知：状态流转时给买卖双方私信会话发 messageType=4 的系统消息。
 * 失败仅记日志，绝不阻断主交易流程（对齐 ReviewServiceImpl#notifyUser 的容错约定）。
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class OrderNoticeService {

    private final ImService imService;

    /** 给买卖双方各发一条系统通知（双方视角的"对方"互为发送者，灰条展示无头像差异） */
    public void notifyOrderEvent(Order order, String eventText) {
        if (order == null || order.getBuyerId() == null || order.getSellerId() == null) {
            return;
        }
        String content = eventText + " #" + order.getOrderNo();
        // 传 productId：通知落进该商品的买卖会话，与"联系卖家"咨询同一会话
        sendTo(order.getSellerId(), order.getBuyerId(), order.getProductId(), content); // 买家收到的
        sendTo(order.getBuyerId(), order.getSellerId(), order.getProductId(), content); // 卖家收到的
    }

    private void sendTo(Long fromUserId, Long toUserId, Long productId, String content) {
        try {
            Conversation conv = imService.getOrCreateConversation(fromUserId, toUserId, productId);
            imService.sendMessage(conv.getId(), fromUserId, toUserId, content, 4, null);
        } catch (Exception e) {
            log.warn("订单通知发送失败: from={}, to={}, err={}", fromUserId, toUserId, e.getMessage());
        }
    }
}
```

### 步骤 2：接入五个触发点

`OrderServiceImpl` 注入 `OrderNoticeService`，在**状态变更成功之后**调用（try-catch 已在组件内，直接调）：

| 方法 | 插入位置 | 调用 |
|---|---|---|
| `pay()` | `orderMapper.updateById(order)` 之后 | `orderNoticeService.notifyOrderEvent(order, "订单已支付，等待卖家发货")` |
| `ship()` | updateById 之后 | `notifyOrderEvent(order, "卖家已发货（" + shipCompany + " " + shipNo + "），请注意查收")`（注意 shipNo 可空，拼字符串前判空） |
| `receive()` | updateById 之后 | `notifyOrderEvent(order, "订单已完成，感谢交易 🎉")` |
| `cancel()` | 条件更新成功（updated>0）且退款逻辑之后 | `notifyOrderEvent(order, "订单已取消：" + (reason == null ? "无" : reason))` |
| `OrderTimeoutTask.cancelTimeoutOrders()` | 每条 updated>0 后 | `orderNoticeService.notifyOrderEvent(order, "超时未支付，订单已自动取消")` |

**事务说明**：这些方法都在 `@Transactional` 里，通知与订单状态同事务落库，一致性有保障；组件内 try-catch 保证通知异常不会把交易回滚。

### 步骤 3：验证（人工用例）

1. 双账号（138/139）走完整流程，**每一步**后双方各自看会话列表：
   - 出现新会话（若没有该商品会话）或未读 +1；
   - 会话预览文案 = 通知文案；
2. 点进聊天页：通知为**居中灰条**（非左右气泡）；
3. 取消分支：买家取消已支付订单 → 灰条"订单已取消…"，且退款同时到账；
4. 超时关单：把一单 created_at 改 31 分钟前，等 1 分钟，自动取消后双方收到灰条；
5. 回归：通知功能失败时不影响下单（把 `OrderNoticeService` 里 sendMessage 临时改成抛异常试一次，记得改回来）。

## 5. 常见坑提醒

- **sender 用对方**：系统消息 sender=接收者的对方，复用现有"灰条"渲染最省事；不要新造 sender=0 的特殊逻辑（过滤器、会话归一化都不认 0）；
- **productId 要传**：不传会落到"无商品会话"，与该商品咨询会话分裂，体验割裂；
- **文案别太长**：会话列表只显示 lastMessage 前若干字。
