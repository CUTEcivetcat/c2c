## M4-1 图片多尺寸缩略图（owner 实施，1~2 天）

**目标**：上传时同时生成 400px 宽缩略图；列表/卡片用缩略图，详情页用原图。首页图片流量降 60%+。

### 改动清单（5 处）

1. **数据库**：`product_image` 加列（sqlgx 留档 + 全量 init.sql 同步）：
   ```sql
   ALTER TABLE `product_image` ADD COLUMN IF NOT EXISTS `thumb_url` VARCHAR(500) DEFAULT NULL COMMENT '400px缩略图地址' AFTER `url`;
   ```
   （MariaDB 语法；同时更新 `sql/init.sql` 的 product_image 建表语句，并在 `sql/sqlgx/` 放时间命名文件）

2. **实体/DTO**：`ProductImage` 加 `thumbUrl`；`ProductVO.ImageVO` 加 `thumbUrl`（Mapper 查询处补字段，检查 `ProductServiceImpl` 里所有 `setUrl` 组装 ImageVO 的地方）。

3. **上传生成**：`FileStorageService.upload()` 保存原图后，用 Java2D 生成缩略图：
   ```java
   private String generateThumb(File original, String datePath, String baseName) throws IOException {
       BufferedImage src = ImageIO.read(original);
       int targetW = 400;
       int targetH = (int) (src.getHeight() * (targetW / (double) src.getWidth()));
       BufferedImage thumb = new BufferedImage(targetW, targetH, BufferedImage.TYPE_INT_RGB);
       Graphics2D g = thumb.createGraphics();
       g.setRenderingHint(RenderingHints.KEY_INTERPOLATION, RenderingHints.VALUE_INTERPOLATION_BILINEAR);
       g.drawImage(src, 0, 0, targetW, targetH, null);
       g.dispose();
       String thumbName = baseName + "_400.jpg";
       File thumbFile = new File(new File(uploadRoot, datePath), thumbName);
       ImageIO.write(thumb, "JPEG", thumbFile);
       return uploadUrlPrefix + "/" + datePath + "/" + thumbName;
   }
   ```
   `baseName` = 去掉扩展名的 uuid；gif 首帧即可（ImageIO 对 gif 只读首帧，可接受）。

4. **发布/编辑写库**：`ProductServiceImpl.publish/update` 组装 `ProductImage` 时 `setThumbUrl(...)`（上传接口返回体里要带上 thumbUrl——改 `UploadController` 返回 map 加 `thumbUrl`，前端发布页存 images 时把 thumbUrl 一并传给后端保存。接口约定：`POST /upload/image` 响应 `{url, thumbUrl}`）。

5. **前端使用**：`ProductCover` 加可选 `thumb-src`（或直接用现有 `:src` 传缩略图）；**列表页**（HomeView/SearchView/FavoriteView/UserProfile/Profile）卡片改传 `p.images?.[0]?.thumbUrl || p.images?.[0]?.url`；**详情页/聊天商品卡保留原图**。

### 存量数据回填（一次性）

对已存在的 `product_image` 记录，原图文件在 `uploads/` 下存在 → 逐条生成缩略图并 UPDATE `thumb_url`。可写个临时 main 类（参考协助方之前的 GenDemoImages 模式），跑完即删或留 `scripts/`。演示图 27 张几分钟跑完。

### 验收

- [ ] 新发布带图商品 → 磁盘出现 `*_400.jpg`，DB `thumb_url` 有值；
- [ ] 首页 DevTools：图片请求 URL 含 `_400`，总流量比之前降 ≥50%；
- [ ] 详情页主图仍是原图（清晰度不降）；
- [ ] 老数据（无 thumb_url）页面不破图（回退原图）；
- [ ] `mvn clean package` + `npm run build` 通过。

## M4-2 压测基线（协作完成，0.5 天）

1. JMeter（已在本机 PATH）新建测试计划 `jmeter/c2c-baseline.jmx`：
   - 线程组：100 并发，Ramp-up 10s，循环 5 分钟；
   - HTTP 请求 Defaults：协议 http、服务器 localhost、端口 8080、路径前缀 `/api/v1`；
   - 4 个取样器（登录用提取器拿 token，其余请求头管理器带 Authorization）：
     | 名称 | 方法 | 路径 | 说明 |
     |---|---|---|---|
     | 登录 | POST | /user/login | JSON：13800000001 / ww123456，正则提取 token |
     | 商品列表 | GET | /product/list?page=1&size=20 | 游客即可 |
     | 商品详情 | GET | /product/1 | 游客即可 |
     | 个人订单 | GET | /order/list?page=1&size=20 | 带 token |
   - 监听器：聚合报告 + 后端监听器存 CSV。
2. 执行基线：后端以 prod 配置启动、`logs` 无大报错，跑 5 分钟；
3. 记录指标到 `docs/压测基线报告.md`：样本数、平均/P90/P95、异常率、吞吐；DevTools 另记首页静态资源总量；
4. 以后 M4-3（WebSocket 等）改造前后各跑一次，对比报告。
