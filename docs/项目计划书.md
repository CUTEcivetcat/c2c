## 一、项目背景与目标

### 1.1 背景与意义

校园闲置交易存在**信息分散、定价困难、信任成本高**三大痛点。项目以"让闲置流转起来"为口号构建 C2C 平台，叠加两层增值：

- **AI 赋能**：智能发布（拍照估价+生成描述）、**智能客服 v1（已上线）**、管理端 AI 助手（W2）——大模型能力统一为"可配置接入 + 规则引擎降级"架构；
- **循环经济社会价值**：低碳看板把成交折算为减排量/省钱额，呼应双碳背景，支撑社科调查报告。

### 1.2 三层目标

| 层 | 目标 | 衡量 |
|---|---|---|
| 功能 | 交易闭环 + AI 助手体系 + 优惠券（G6） | §5 全部任务 DoD 达成 |
| 技术 | 安全、事务正确、工程规范 | 46 自动化测试（43 后端+3 前端）常绿、CI 生效 |
| 论文 | 七件套 + 两组实验数据 | §6.5 清单全勾 |

### 1.3 范围边界（不做什么）

不做直播/拼团等二手主线外功能；不上微服务（单体 + delegate 委派已正名）；支付以支付宝沙箱为准（G1 搁置中）；IM 轮询为主，WebSocket 视时间（M4-3）；AI 不引入 Spring AI（见《K50本地模型对接》）。

## 二、总体架构与技术栈

```
三端：Vue3 用户端(5173) · Vue3 管理端(5174) · 微信小程序
后端：Spring Boot 2.7 单体（JWT 三级权限 / MyBatis-Plus / Redis 缓存）
存储：MariaDB 13(主, .14) · MySQL 5.7(备, .11) · 本地磁盘 uploads（/files 映射）
AI：OpenAI 兼容客户端 —— 云 API(生产) / K50 OlliteRT(开发测试, 零成本)；无 Key 自动降级规则引擎
```
