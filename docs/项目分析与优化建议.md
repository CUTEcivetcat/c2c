# 青禾集市（c2c）项目分析与优化建议

> 分析时间：2026-10-29（2026-10-31 更新：S4/S5/S7/C1/C4/C5/C6 已按 M1 修复，S1/S2/S3 此前已修复，状态以《安全修复待办清单.md》为准；剩余重点为 M2 订单状态机与工程化项）
> 分析范围：后端（Spring Boot 2.7 单体，157 个 Java 文件）、用户端前端（Vue3）、管理端前端、微信小程序、数据库脚本、部署配置、docs/ 现有文档
> 结论依据：逐文件代码核查 + 与《安全修复待办清单.md》逐项比对复核
> 姊妹篇：《安全修复待办清单.md》（已同步更新复核状态）

## 1. 总体结论

项目功能闭环完整（用户/商品/订单/IM/钱包/审核/后台/AI/低碳），代码分层清晰、中文注释齐全、安全基建意识良好（外部化配置、JWT 启动校验、上传三重校验、原子扣款等已落地）。

**当前最值得投入的不是新功能，而是三类债：**

1. **安全债**：8 月审计遗留的 P1 级条目多数仍未修复，且本次复核**新发现 1 个高危配置问题**（验证码回显开关默认值与注释相反，见 2.1-S1）。
2. **正确性债**：订单状态机存在不可达分支与恒真判断，评价接口缺订单参与校验，资金/评价可被滥用或刷数。
3. **工程化债**：157 个后端文件仅 3 个测试类、无 CI、伪 Feign 命名误导、README 与代码现状脱节。

## 3. 优化建议（按优先级）

### 3.1 P0 —— 建议两周内完成（安全正确性，改动小收益大）

1. **修复 S1（一行改动，收益最大）**：`application.yml` 中 `sms-echo-code` 默认值改为 `false`，仅在 `application-test.yml` 显式置 true；同时核对生产 `config/application-prod.yml` 必须显式 `APP_SMS_ECHO_CODE=false` 或删除该 key 的覆盖。
2. **修复 S2 评价校验**（约 30 行）：`RatingService.submit` 按 orderId 查订单，校验「评价人 ∈ {buyer, seller}」「订单 status=4 已完成」「role 与身份一致（买家评卖家/卖家评买家）」，并按被评人方向防双向重复。这同时堵死刷信誉分。
3. **修复 S3 管理登录锁定**（复用用户侧 `checkLoginLock/failLoginLock` 模式，约 20 行）：`AdminAuthController.login` 加 Redis 失败计数，15 分钟 5 次锁死，并对 account 做发送端无关的统一定时窗口。
4. **修复 S4 refreshToken 隔离**（约 40 行）：签发时加 `type=refresh` claim；新增 `POST /user/refresh` 专用端点校验后换发短时 access token；过滤器对 refresh token 拒绝放行业务接口；改密/注销时删除 Redis `refresh:token:{userId}`。
5. **修复 C1 地址快照转义**（约 10 行）：`buildAddressSnapshot` 改用 `ObjectMapper.writeValueAsString(Map)`，删除手工拼接。
6. **修复 C4/C5**：订单号后缀改 `SecureRandom` 并给 `order_no` 加唯一索引冲突重试；`LOCKS` 改为 Guava `Striped` 或带 size 上限的清理策略。

**验证方式**：`mvn clean package -DskipTests` 通过；用两个账号走「下单→支付→双方互评」验证越权评价被拒；管理端故意输错 5 次密码验证锁定；抓包确认验证码响应无 code 字段。

### 3.2 P1 —— 建议一个月内完成

7. **S5 token 版本化**：`user` 表加 `token_version`，登录时写入 claim，过滤器比对当前库值；封禁/改密/角色变更时递增。同步解决权限调整后旧 token 残留问题（替代现在的「重新登录才生效」）。
8. **S6 日志脱敏**：`RequestLogFilter` 对 query 做参数白名单/黑名单脱敏（手机号、email、code、token 一律打码），或改为只记 path + 关键 pathVariable。
9. **S7 微信 mock 加闸**：`wechat.mock=true` 时启动打印醒目警告并要求 `spring.profiles.active != prod`；prod 下 mock=true 直接拒绝启动（对齐 JWT 密钥启动校验的做法）。
10. **C2/C3 订单状态机整理**：按《真实支付接入方案.md》落地「0 待支付 → 1 已支付(托管) → 2 已发货 → 3 已收货 → 4 完成 / 5 取消」，删除自动完成与恒真判断；即便暂不接真实支付，也把 balance 支付改为「status=1 托管」，让 ship/receive 链路真正可用——这是当前演示模式与界面文案最大的出入。
11. **C6 入参边界**：`ProductCreateDTO` 加 `@DecimalMin("0.01")`、`@Size(max=200)` 等；全局检查其他 DTO 同类问题。
12. **E1/E2 最小测试与 CI**：先给钱包（扣款/退款/流水）、订单状态机、评价校验写 5-8 个核心单测；Gitee/GitHub 加一条流水线：`mvn test` + 前端 `npm run lint && npm run build`。
13. **E3/E4 文档对齐**：决定默认 profile（建议仓库内默认 test，prod 仅服务器注入），同步 README 的项目结构、SQL 说明，删除 blog/ 等失效引用。

### 3.3 P2 —— 季度级改进

14. **真实支付落地**：按《真实支付接入方案.md》阶段一接入微信 JSAPI/支付宝之一，替换 S1 同款演示充值（依赖商户资质）。
15. **P-b/P-d 图片与存储**：接入 OSS/COS，上传走服务端直传 + 预签名；生成 200/400/800 三档缩略图；Nginx 静态资源加 `expires` + CDN。
16. **P-a 浏览量削峰**：Redis `INCR` + 每 10 分钟批量落库，或至少给详情接口加防刷限制（同 IP 同商品 1 分钟计 1 次）。
17. **P-c IM 升级**：WebSocket（或 SSE）替代轮询；会话未读数用消息表聚合校准，消除双写不一致。
18. **S8 演示口令治理**：生产部署脚本里强制 `UPDATE user SET password=... WHERE id IN (种子账号)` 或首次登录强制改密。
19. **S9 小程序合法域名**：域名 + HTTPS（可复用后端 Nginx 证书），`weapp` serverUrl 改域名并支持配置化。

### 3.4 P3 —— 视发展方向决定

20. **C7 伪 Feign 清理**：要么删掉 feign 包改直接注入 Service/Mapper（推荐，单体下最诚实），要么真拆微服务时换 Spring Cloud OpenFeign。当前形态对新人误导最大。
21. **E6 显式日志策略**：`logback-spring.xml` 定死滚动与保留；接入 actuator `prometheus` 端点 + 简单 Grafana，替代肉眼查日志。
22. **E5 工作区清理**：删除 `img.png`、清理 `logs/node_modules`；`scripts/` 若不再使用可归档到独立分支。
