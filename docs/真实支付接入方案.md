# C2C 平台真实支付接入文档

> 状态：**规划中（未实施）** · 当前支付为「模拟充值 + 余额扣款」演示模式
> 适用版本：后端 Spring Boot 2.7 单体（`src/main/java/com/c2c`）

---

## 1. 现状（演示模式）

当前支付链路（`OrderServiceImpl.pay`，订单状态机）：

```
买家下单(status=0) → 点击支付 → 余额扣款(deductBalance)
  → 平台托管金额 → 立即「自动发货 + 自动确认收货」→ 打款给卖家(status=4)
```

**问题**：
- 充值接口 `WalletController.recharge` 直接加余额，无真实支付渠道，等于免费余额
- 支付不区分渠道，无第三方支付单号、无回调校验
- 托管资金只是逻辑字段，没有真实资金归集

---

## 2. 目标流程（真实支付）

### 2.1 建议的支付渠道
| 渠道 | 适用 | 接入成本 | 说明 |
|---|---|---|---|
| 微信支付（JSAPI / 小程序支付） | 小程序 + 网页 | 中 | 需已认证公众号/小程序 + 商户号 |
| 支付宝（当面付 / 电脑网站支付） | 网页端 | 中 | 需企业支付宝 + 应用 |

> 建议：小程序用**微信支付 JSAPI**（wx.requestPayment），网页端先接入支付宝或微信 Native，二选一先跑通。

### 2.2 目标状态机（改造后）
```
下单(status=0, 待支付)
  → 创建支付单 → 调第三方统一下单 → 返回 prepay 参数
  → 用户支付 → 第三方回调（验签）→ 校验金额/订单号/状态
  → status=1(已支付, 资金进入平台托管 escrow)
  → 卖家发货 status=2 → 买家确认收货 status=3 → 打款给卖家 status=4
  → 超时未支付 → 关单 status=5(已取消) → 恢复商品在售
```

## 3. 改造点清单

### 3.1 数据表（`sql/tables/` 新增）
```sql
-- 支付单表
CREATE TABLE payment_order (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  order_id BIGINT NOT NULL,              -- 关联 c2c 订单
  buyer_id BIGINT NOT NULL,
  channel VARCHAR(20) NOT NULL,          -- wechat / alipay / balance
  trade_no VARCHAR(64),                  -- 第三方交易号
  out_trade_no VARCHAR(64),              -- 商户订单号(我们的单号)
  amount DECIMAL(10,2) NOT NULL,
  status TINYINT NOT NULL DEFAULT 0,     -- 0待支付 1已支付 2已退款 3已关闭
  pay_time DATETIME,
  notify_time DATETIME,
  created_at DATETIME,
  updated_at DATETIME,
  UNIQUE KEY uk_out_trade_no (out_trade_no)
);
```

### 3.2 后端新增/改动
| 文件 | 改动 |
|---|---|
| `order/service/OrderService` | `pay()` 拆分为「创建支付单 + 回调确认」两段；取消「自动完成」 |
| 新增 `pay/PaymentService` | 封装统一下单、回调验签、查询、退款 |
| 新增 `pay/PaymentController` | 暴露 `/payment/create`（下单）、`/payment/notify/{channel}`（回调，**公网可达**） |
| `order/service/OrderServiceImpl` | 支付成功后：status 0→1，资金入 `escrow`，**不自动发货**，改由卖家手动发货 |
| `wallet/service/WalletService` | 增加 `releaseEscrow(卖家收款)`，确认收货后打款 |
| 取消订单逻辑 | 已支付订单取消 → 退款回买家 |

### 3.3 前端/小程序改动
| 端 | 改动 |
|---|---|
| 网页端 | 支付页调 `/payment/create` 拿 prepay → 微信 JSAPI `wx.chooseWXPay` / 支付宝 `alipay-sdk` |
| 小程序 | `requestPayment` 拉起支付，成功后刷新订单状态 |
| 钱包页 | 充值按钮改调真实支付渠道，不再直接加余额 |

## 4. 微信支付接入步骤（JSAPI）

### 4.1 前置
- 已认证服务号/小程序 + 微信支付商户号（mch_id）
- 商户 API v3 密钥（32 位）与商户证书（apiclient_cert.pem / apiclient_key.pem）
- 回调域名必须为 **HTTPS** 且公网可访问

### 4.2 配置（`config/application-prod.yml`，不提交仓库）
```yaml
wechat-pay:
  app-id: ${WXPAY_APPID:}
  mch-id: ${WXPAY_MCHID:}
  api-v3-key: ${WXPAY_API_V3_KEY:}
  private-key-path: ${WXPAY_PRIVATE_KEY:/softservice/c2c/pay/apiclient_key.pem}
  notify-url: ${WXPAY_NOTIFY_URL:https://你的域名/api/v1/payment/notify/wechat}
```

### 4.3 核心时序
```
1. 前端 POST /payment/create {orderId, channel:"wechat"}
2. 后端：校验订单状态=0 → 生成 out_trade_no → 调微信 v3 统一下单(JSAPI, openid)
   → 返回 prepay_id + 用 api-v3-key 签名 → 返回 wx.requestPayment 所需参数
3. 前端 wx.requestPayment({timeStamp, nonceStr, package:"prepay_id=xxx", signType:"RSA", paySign})
4. 微信支付成功 → 异步回调 POST /payment/notify/wechat
   → 验签（AES-256-GCM 解密 + 签名校验）→ 校验金额/商户号/状态
   → 幂等更新 payment_order.status=1 + order.status=1 + escrow=amount
5. 前端轮询 /payment/status 或等回调后刷新订单
```

### 4.4 安全要点
- **回调必须验签 + 解密**，禁止信任明文 body
- **金额校验**：回调金额必须等于订单金额，防止篡改
- **幂等**：同一 out_trade_no 重复回调只处理一次（数据库唯一键 + 状态判断）
- **HTTPS**：统一下单与回调必须走 HTTPS
- **敏感配置不入库**：商户号/密钥/证书走环境变量 + 外部配置

## 5. 支付宝接入步骤（可二选一，先跑通其一）

```
1. 前端 POST /payment/create {orderId, channel:"alipay"}
2. 后端：支付宝 SDK(alipay-sdk-java) 调 alipay.trade.page.pay / wap.pay
   → 返回支付表单/URL，前端跳转
3. 用户支付完成 → 异步通知 POST /payment/notify/alipay
   → 用支付宝公钥验签（RSA2）→ 校验 app_id/out_trade_no/total_amount/status
   → 幂等更新支付单与订单状态
4. 对账：每日 alipay.trade.query 核对未完成订单
```

---

## 6. 建议的迭代顺序

1. **阶段一（最小可用）**：接微信支付 JSAPI 或支付宝，打通「下单 → 支付 → 回调 → 订单状态=已支付」
   - 充值接口改真实渠道；「托管 + 自动完成」改为「托管 + 卖家手动发货 + 买家确认收货 + 打款」
2. **阶段二（资金安全）**：退款能力（取消订单退 escrow）、支付单查询/对账、超时关单
3. **阶段三（风控）**：支付限额、频次控制、异常订单标记、资金流水审计
