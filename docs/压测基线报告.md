## 2. 测试计划结构

测试计划 `jmeter/c2c-baseline.jmx`，元件树如下：

```
Test Plan
├── HTTP Request Defaults        # 公共服务器/端口/路径前缀
├── HTTP Header Manager          # 全局 Content-Type
├── Thread Group（线程组）
│   ├── CSV Data Set（result/perf-tokens.csv：userId,token,account；循环复用）
│   ├── 1. 登录 POST /user/login（默认禁用，基线不压登录接口）
│   ├── 2. 商品列表 GET /product/list
│   ├── 3. 商品详情 GET /product/1
│   ├── 4. 个人订单 GET /order/list（Authorization: Bearer ${token}）
│   ├── Aggregate Report（聚合报告）
│   ├── Backend Listener → CSV（结果落盘）
│   └── View Results Tree（仅调试用，正式压测可关）
```

## 3. 元件配置明细

### 3.1 HTTP Request Defaults（默认请求）

| 字段 | 值 |
|---|---|
| Protocol | `http` |
| Server Name or IP | `localhost` |
| Port Number | `8080` |
| Path | `/api/v1` |

### 3.2 HTTP Header Manager（全局）

| Name | Value |
|---|---|
| Content-Type | `application/json` |

### 3.3 Thread Group（线程组）

| 字段 | 值 | 说明 |
|---|---|---|
| Number of Threads (users) | `100` | 并发用户数 |
| Ramp-up period (seconds) | `10` | 10 秒内逐步起满 100 线程 |
| Loop Count | 勾选 `Infinite` | 时长由调度器控制 |
| Scheduler（调度器） | 勾选 |  |
| Duration (seconds) | `300` | 持续压测 5 分钟 |

### 3.4 鉴权：CSV Data Set（token 预签）

压测前先跑 `PerfTokenGeneratorTest`，从库内读普通买家按当前 `jwt.secret` 签出 token，导出 `jmeter/result/perf-tokens.csv`（列：`userId,token,account`）。线程组开头的 CSV Data Set 读入 `${userId}` / `${token}` / `${account}`，订单取样器用 `${token}` 拼鉴权头；可用账号少于 100 线程时 `recycle=true` 循环复用。

| 字段 | 值 |
|---|---|
| CSV File | `result/perf-tokens.csv` |
| 变量名 | `userId,token,account` |
| Recycle on EOF | 是（循环复用） |

> 登录取样器默认 `enabled=false`：基线不压登录接口，避免单账号实时登录被频控/验证码拦截；需要压登录时在 JMeter 里重新启用，正则提取的 token 会覆盖 CSV 变量。生成脚本与口径见 `jmeter/README.md` §3.1。

### 3.5 取样器 2：商品列表（GET，游客即可）

| 字段 | 值 |
|---|---|
| Method | `GET` |
| Path | `/product/list` |
| Parameters | `page=1`，`size=20` |

### 3.6 取样器 3：商品详情（GET，游客即可）

| 字段 | 值 |
|---|---|
| Method | `GET` |
| Path | `/product/1` |

### 3.7 取样器 4：个人订单（GET，需登录）

| 字段 | 值 |
|---|---|
| Method | `GET` |
| Path | `/order/list` |
| Parameters | `page=1`，`size=20` |

**该取样器下挂 HTTP Header Manager**（或用全局头管理器引用变量）：

| Name | Value |
|---|---|
| Authorization | `Bearer ${token}` |

> 鉴权由过滤器解析 Bearer token 后注入 `X-User-Id`，无需手动传用户 ID。

### 3.8 监听器

- **Aggregate Report（聚合报告）**：直接查看 `#Samples / Average / 90th pct / 95th pct / Error % / Throughput`。
- **Backend Listener → CSV**：输出路径 `jmeter/result/c2c-baseline.csv`，逐样本落盘便于复盘。
- **View Results Tree**：仅在联调阶段打开确认请求/响应正常，正式 5 分钟压测时关闭，避免渲染拖慢压测端。

## 4. 执行步骤

1. 按 §1 启动后端，确认接口可通（浏览器或 Postman 调一次 `/api/v1/product/list?page=1&size=3`）。
2. 打开 JMeter，按 §2、§3 搭好计划，先跑 1~2 个线程、1 轮联调：确认登录拿到 token、订单接口返回 200 而非 401。
3. 关闭 View Results Tree，线程组恢复 100 并发、持续 300 秒。
4. 启动压测，观察后端日志无持续报错、无 OOM；压测期间不要做其他重操作。
5. 结束后从聚合报告 / CSV 抄录 §5 指标。

## 7. 注意事项

- 本基线只压**查询接口**；下单/支付/发货/取消等写接口不在本轮范围，避免产生脏订单。
- 鉴权：token 由 `PerfTokenGeneratorTest` 预签进 `result/perf-tokens.csv`，CSV Data Set 循环复用；基线不压登录接口（登录取样器默认禁用），避免单账号实时登录被频控/验证码拦截。
- 压测本机即后端，压测端与服务端同机，吞吐数值会受本机资源限制；结论用于**前后对比**与相对瓶颈判断，不等同生产容量。
- JMeter 与后端都用 JDK17 启动；若 JMeter 启动报版本错误，检查 `JAVA_HOME`。
