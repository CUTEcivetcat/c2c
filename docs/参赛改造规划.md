# 「青禾集市」挑战杯参赛改造规划

**AI 智能发布 × 低碳循环数据看板**

> 配套图：`docs/改造架构图.html`
> 基线版本：现有 c2c 主分支（Spring Boot 2.7 单体 + Vue3 双前端 + 微信小程序）
> 范围：只做增量改造（①AI 拍照估价 ②AI 自动生成描述 ⑤低碳数据看板），不动现有交易闭环。

---

## 1. 改造目标与参赛定位

在现有平台基础上叠加三项差异化能力，形成挑战杯「科技发明 B 类」技术亮点与「哲学社会科学类调查报告」的数据支撑：

| 能力 | 解决的用户痛点 | 参赛价值 |
|---|---|---|
| ① AI 拍照估价 | 卖家不知道定多少钱 | 技术亮点：多模态识别 + 历史成交价修正 |
| ② AI 自动生成描述 | 发布商品费时费力 | 技术亮点：一键智能发布 |
| ⑤ 低碳循环看板 | 平台社会价值不可见 | 社科报告数据支撑：减排量/省钱金额可量化 |

**设计原则**：大模型能力做成「可配置接入」——配置了 API Key 走真实大模型，未配置自动降级为本地规则引擎，保证任何时候功能可用、可演示、可答辩。

## 3. 后端设计

### 3.1 新增 ai 模块（`src/main/java/com/c2c/ai/`）

#### 文件清单

| 文件 | 说明 |
|---|---|
| `AiProperties.java` | `@ConfigurationProperties("app.ai")` 配置类：baseUrl / apiKey / model / timeout |
| `AiController.java` | `POST /ai/intelligent-publish`，登录用户可调 |
| `AiService.java` / `AiServiceImpl.java` | 核心逻辑：大模型调用 → JSON 解析 → 规则引擎兜底 → 历史成交价修正 |
| `dto/AiPublishRequest.java` | 入参：`imageUrl`（必填，首图 URL）、`categoryId`（可选，用户已选分类时传入） |
| `dto/AiPublishVO.java` | 出参：`title`、`description`、`categoryId`、`categoryName`、`condition`(1~4)、`priceMin`、`priceMax`、`source`(`model`/`rule`) |
| `AiOpenAiClient.java` | 大模型 HTTP 调用封装（Hutool `HttpUtil`，OpenAI 兼容协议） |
| `mapper/ProductPriceMapper.java` | 同分类历史成交价查询（或直接复用 ProductMapper 加方法） |

#### 接口定义

**`POST /api/v1/ai/intelligent-publish`**（需登录）

```json
// 请求
{ "imageUrl": "http://host/files/xxx.jpg", "categoryId": 12 }

// 响应（R<AiPublishVO>）
{
  "code": 200, "message": "success",
  "data": {
    "title": "九成新高等数学（同济第七版）上下册",
    "description": "正版教材，无笔记划痕，书脊完好，适合本学期课程使用。",
    "categoryId": 12,
    "categoryName": "教材教辅",
    "condition": 2,
    "priceMin": 8.00,
    "priceMax": 18.00,
    "source": "model"
  }
}
```

#### 核心流程（AiServiceImpl）

1. 入参校验：`imageUrl` 非空；用 Hutool `Validator`/`StrUtil` 校验。
2. **优先走大模型**（`ai.api-key` 非空时）：
   - 组装消息：`[{role:system, content: 系统提示词}, {role:user, content: [{type:text}, {type:image_url, image_url:{url}}]}]`
   - 系统提示词要点（写死在常量里，中文）：
     - 你是二手交易平台的智能发布助手；
     - 根据图片识别物品类别、成色、品牌型号（能识别则写）；
     - 只输出一个 JSON 对象，字段：`title`（≤30字）、`description`（≤100字）、`categoryName`（匹配平台两级分类名）、`condition`（1全新/2几乎全新/3轻微使用/4明显使用）、`priceMin`、`priceMax`（按二手行情给建议区间）；
     - 不确定的信息用空字符串，禁止编造。
   - 解析响应 `choices[0].message.content`，用 Hutool `JSONUtil` 解析；`categoryName` 需与 `category` 表匹配（模糊/精确），匹配不到则 `categoryId=null` 由前端提示用户手选。
   - 调用失败 / 超时 / JSON 解析失败 → 捕获异常，**降级规则引擎**（`source=rule`）。
3. **规则引擎兜底**（无 Key 或降级时）：
   - 无法识别图片内容，直接给出通用建议：`title` 留空（由用户填）、`condition=2`、`priceMin/priceMax` 由第 4 步历史均价 ±20% 计算；
   - 若请求带了 `categoryId`，`categoryName` 从分类表查出回填。
4. **历史成交价修正**（两种路径共用）：
   - `ProductPriceMapper`：查 `product` 表同 `category_id` 且 `status=3`(已售) 的商品，`AVG(price)` 与 `COUNT(*)`；
   - 有历史数据：`priceMin = avg*0.8, priceMax = avg*1.2`（保留两位小数）；无历史数据：大模型给出的区间原样返回；模型也没给 → 返回 `null` 区间（前端不展示建议价）。
5. **Redis 缓存**：key=`ai:publish:{md5(imageUrl)}`，TTL 24h；命中直接返回（减少大模型调用成本）。

#### 大模型接入（AiOpenAiClient）

- 协议：OpenAI 兼容 `POST {baseUrl}/chat/completions`（豆包/通义/DeepSeek 等均兼容，都支持 vision 的模型即可）。
- 请求体：`model`、`messages`、`max_tokens: 300`、`temperature: 0.3`。
- 头：`Authorization: Bearer {apiKey}`、`Content-Type: application/json`。
- 超时：连接/读取均设 `timeout`（默认 15s），用 Hutool `HttpRequest.timeout(...)`。
- **注意**：微信小程序端暂不做 AI（规划外），只在 Web 用户端接入。

#### 配置项（`application.yml` + `config/` 外部覆盖）

```yaml
app:
  ai:
    base-url: ${AI_BASE_URL:}        # 如 https://ark.cn-beijing.volces.com/api/v3
    api-key: ${AI_API_KEY:}          # 为空 = 规则引擎模式
    model: ${AI_MODEL:doubao-1-5-vision-pro-250828}
    timeout: ${AI_TIMEOUT:15000}
```

- `src/main/resources/application.yml` 只放占位符（现有脱敏惯例）；
- 真实 Key 放 `config/application-pro.yml`（已被 .gitignore 排除）。

#### 常量与鉴权改动点（2 处）

1. `ApiPath.java` 新增：
   ```java
   String AI = "/ai";
   String AI_INTELLIGENT_PUBLISH = "/ai/intelligent-publish";
   ```
2. `AuthTokenFilter`：**无需改**——`/ai/**`、`/eco/**` 默认按「普通用户接口」走登录鉴权（不在白名单/只读名单即可，默认如此）。

### 3.2 新增 eco 模块（`src/main/java/com/c2c/eco/`）

#### 文件清单

| 文件 | 说明 |
|---|---|
| `EcoController.java` | 三个接口：用户统计 / 平台总览 / 趋势 |
| `EcoService.java` / `EcoServiceImpl.java` | 统计聚合 + 减排换算 |
| `dto/UserEcoStatsVO.java` | 我的环保贡献出参 |
| `dto/PlatformEcoVO.java` | 平台总览出参 |
| `dto/EcoTrendVO.java` | 趋势出参（日期 + 减排量） |
| `mapper/EcoOrderMapper.java` | SQL 聚合（join product 取 category_id / original_price） |

#### 接口定义

**`GET /api/v1/eco/user/stats`**（需登录，当前用户）

```json
{
  "code": 200,
  "data": {
    "dealCount": 12,          // 成交笔数（作为买家或卖家，已完成订单）
    "saveMoney": 156.50,      // 省钱金额（仅算买家：Σ(原价-成交价)，无原价不计）
    "carbonReduceKg": 68.2,   // 减排量 kg CO₂e（估算口径，见下）
    "treeEquivalent": 4       // 相当于植树（减排量 / 18kg，向下取整）
  }
}
```

**`GET /api/v1/admin/eco/overview`**（管理端，需 ADMIN + DASHBOARD 权限）

```json
{
  "code": 200,
  "data": {
    "totalDealCount": 356,
    "totalSaveMoney": 4520.00,
    "totalCarbonReduceKg": 1980.5,
    "totalTreeEquivalent": 110
  }
}
```

**`GET /api/v1/admin/eco/trend?days=30`**（管理端，需 ADMIN + DASHBOARD 权限）

```json
{
  "code": 200,
  "data": {
    "dates": ["2026-09-15", "..."],
    "carbonReduceKg": [12.5, "..."]   // 按成交完成日期分组
  }
}
```

#### 统计口径（必须按此实现，文档同步标注「估算口径」）

- **成交笔数**：`order` 表 `status=4`(已完成)；用户统计时 `buyer_id=当前用户 OR seller_id=当前用户`。
- **省钱金额**：`order.price` 对应的 `product.original_price`（join），`original_price - price` 为正才计入，且只算买家侧（`buyer_id=当前用户`）。
- **减排量（kg CO₂e）**：按商品一级分类系数估算（平台口径，参考国际二手循环研究常见量级）：

  | 一级分类 | 系数（kg CO₂e/件） |
  |---|---|
  | 教材教辅 / 书籍 | 2.5 |
  | 数码电器 / 电脑办公 | 10 |
  | 服饰鞋包 / 运动户外 | 6 |
  | 美妆护肤 / 生活家居 | 4 |
  | 其他 / 分类缺失 | 5 |

  - 实现：`order join product` 拿 `category_id` → join `category` 拿一级分类名 → 字典映射系数；映射不到用默认 5。
  - 每笔已完成订单计一次减排量（不区分买卖双方）。
- **相当于植树**：`减排量 / 18`（一棵树年固碳量估算值），向下取整。
- **趋势**：`GROUP BY DATE(complete_time)`，按 `days` 参数（默认 30，上限 90）返回。

> ⚠️ 实现注意：`order` 表只有 `product_title`/`price` 快照，**没有** `category_id`/`original_price`，必须 `LEFT JOIN product` 取；被删除商品（级联删除场景）join 不到时按「其他 5kg」系数、省钱不计入，保证统计不报错。

#### 常量与鉴权改动点（3 处）

1. `ApiPath.java` 新增：
   ```java
   String ECO_USER_STATS = "/eco/user/stats";
   String ADMIN_ECO_OVERVIEW = "/admin/eco/overview";
   String ADMIN_ECO_TREND = "/admin/eco/trend";
   ```
2. `AuthTokenFilter.permForPath()` 新增一行，映射到现有看板权限码：
   ```java

   ```
3. `AdminPerm` 无需改（复用 DASHBOARD）。

## 4. 前端设计

### 4.1 用户端发布页（`frontend/src/views/ProductPublishView.vue`）

**交互流程**：

1. 现有「上传商品图」首图上传完成后，在首图下方出现按钮 **「✨ AI 智能填写」**；
2. 点击 → 调 `POST /ai/intelligent-publish`（body: 首图 URL + 当前已选分类，若有）；
3. Loading 态按钮文案「AI 分析中…」、禁用防重复点击；失败（网络/400）→ `ElMessage.error`，不阻塞手动填写；
4. 成功回填：
   - `title` → 标题输入框；
   - `description` → 描述输入框；
   - `categoryName` → 自动匹配选中分类（匹配不到提示用户手动选）；
   - `priceMin/priceMax` → 在价格输入框下方渲染提示条：「AI 建议价：¥8 ~ ¥18」+ 按钮「采用」/「忽略」；
   - `condition` → 成色下拉选中。

**改动建议**：抽一个 `frontend/src/api/ai.js`（或并入现有 api 封装），暴露 `intelligentPublish(imageUrl, categoryId)`；组件内新增 `aiLoading`、`aiSuggestion` 两个 ref 与回填逻辑。

### 4.2 用户端个人中心（`frontend/src/views/ProfileView.vue`）

- 在个人资料/统计区域新增卡片 **「我的环保贡献」**（登录用户可见）：
  - 数据来自 `GET /eco/user/stats`；
  - 展示：成交笔数、累计省钱（元）、减排量（kg CO₂e）、相当于植树（棵）；
  - 配一句文案：「你的每一次闲置流转，都在为地球减碳」；
  - 加载失败静默隐藏该卡片（不阻塞页面）。

### 4.3 管理端仪表盘（`admin-frontend/src/views/DashboardView.vue`）

- 新增 **「低碳循环看板」** 区块（在现有 7 日/30 日趋势图旁边）：
  - 三个统计卡：平台累计减排量（kg CO₂e）、累计省钱金额（元）、累计成交笔数 → `GET /admin/eco/overview`；
  - 一个折线图：近 30 日减排趋势 → `GET /admin/eco/trend?days=30`，复用现有 ECharts 封装与样式；
  - 权限：次级管理员需勾选「数据大屏」权限（复用 DASHBOARD 权限码，管理端权限勾选无需改）。

## 7. 风险与注意事项

1. **大模型幻觉**：标题/分类可能不准 → 系统提示词强制「不确定就留空」，前端始终允许手动修改，分类匹配不到不自动选中。
2. **成本**：每次发布调用一次大模型 → Redis 24h 缓存按图去重；演示现场可预生成。
3. **减排系数属估算口径**：答辩时明确说明「系数为平台设定口径，数据来自平台真实成交」，不要声称权威机构标准。
4. **鉴权**：`/admin/eco/**` 必须走管理端鉴权（`isAdminPath` 已覆盖 `/admin/` 前缀），别放到 `/eco/` 下裸奔。
5. **不改现有代码**：所有新代码独立新包；如必须动 `ApiPath`/`AuthTokenFilter`/`application.yml`，改动极小且已在上文标注。
