# 青禾集市（c2c）作为毕业设计的可行性分析

> 分析时间：2026-10-29
> 分析前提：本科计算机/软件工程类毕业设计（设计+论文，非纯论文）；项目现状以本仓库 2026-10-29 代码为准
> 配套文档：《毕业设计完善路线.md》（缺口补齐计划，本文档的续篇）

---

## 1. 结论摘要

**总体判断：可行，且属于「中上底子的优质毕设坯子」，但按现状直接送审只能拿「合格~中等」，需按《毕业设计完善路线.md》补齐 4 个短板后才具备冲「良好~优秀」的条件。**

一句话概括：**功能完整度已经 85 分，工程证据和创新论证目前只有 60 分**——毕设评的不是"功能多"，而是"问题定义清楚、方案有依据、实现有验证、结论有数据"。

| 维度 | 现状评分 | 说明 |
|---|---|---|
| 功能完整性 | ★★★★☆ | 用户/商品/交易/IM/钱包/审核/后台/AI/低碳/小程序十大模块闭环，超出一般电商毕设 |
| 技术栈主流度 | ★★★★☆ | Spring Boot + Vue3 + 微信小程序 + Redis + JWT，答辩老师熟悉、问题好答 |
| 业务复杂度 | ★★★★☆ | 担保交易状态机、三级权限、审核流，有"可讲的设计决策" |
| 创新点 | ★★★☆☆ | AI 智能发布 + 低碳看板有差异化，但**缺实验数据支撑**，目前只能算"功能亮点"不能算"创新论证" |
| 工程规范与测试 | ★★☆☆☆ | 无 CI、单测 3 个、无压测数据——这是送审最大的硬伤 |
| 论文素材现成度 | ★★★☆☆ | ER 图/接口文档/Swagger/部署文档现成；需求规格/测试报告/实验数据需补 |
| 演示效果 | ★★★★☆ | 三端可演示，AI 拍照发布现场效果抓人 |

## 2. 对照毕业设计评分标准的逐项分析

### 2.1 选题与需求分析（权重通常 10~15%）

- **符合度**：C2C 二手交易是经典选题，需求真实、用户角色清晰（买家/卖家/管理员/审核员），边界明确。✅
- **风险**：选题偏"传统电商管理系统"，**必须靠 AI 与低碳两个差异点把选题名称拉开**（见 §4.1），否则容易被归为"千篇一律的商城系统"。
- **需补**：正规需求规格说明书（用例图、用例描述、非功能需求）——现状只有 README 功能表。

### 2.2 系统设计（20~30%）

**强项（可直接写成章节）**：
- 数据库设计：19 表、字段注释齐全、索引设计有章法（联合索引/唯一约束/全文索引）、有 ER 图（README）；
- 接口设计：REST 风格统一 + Swagger 在线文档 + ApiPath 常量集中管理；
- 安全设计：JWT + 过滤器三级鉴权、配置外部化、上传三重校验、原子扣款——这一块比多数毕设扎实；
- 部署架构：Nginx 静态托管 + 反代、外部化配置、双前端分离。

**弱项（需补或谨慎处理）**：
- 订单状态机有死代码与不可达分支（C2/C3），**论文里画状态图前必须先按优化路线 M2 整理**，否则答辩时被问到「ship 接口什么时候被调用」会翻车；
- 「Feign 客户端」是本地直调，论文架构图若按微服务画属于**虚构架构**，必须按单体如实描述（或按 M3.3 先改名）。

### 2.3 实现（20~30%）

- 代码量与分层：157 个 Java 文件 + 双前端 34 个页面 + 小程序，规模充足；Controller/Service/Mapper/DTO 分层规范。✅
- 已知安全/正确性缺陷（S1~S12、C1~C9）必须在送审前修复 P0/P1 部分——评阅老师若发现「验证码回显默认开启」「评价可刷信誉分」这类问题，印象分会直接掉档。
- 演示数据充分（data.sql 30 商品覆盖全分类）。

### 2.4 测试（10~20%）——**当前最大短板**

- 现状：3 个测试类、无测试报告、无性能数据。
- 毕设要求通常至少：功能测试用例表 + 单元/集成测试 + （较好的学校要求）性能或对比实验。
- **缺口即机会**：资金安全（并发扣款）和 AI 估价准确率是两个天然适合做"实验章节"的题材（见 §4.2）。

### 2.5 文档与答辩（10~20%）

- 现成：README、COMMON.md、sql/README、Swagger（接口文档）、部署文档——工程文档底子好。
- 需补：需求规格说明书、概要设计、详细设计、测试报告、用户手册（论文附录用）。
- 演示：建议准备「买家下单→卖家发货→AI 发布→低碳看板数据变化」一条 3 分钟主线 + 管理端权限演示 1 分钟。

## 3. 工作量与周期评估

| 事项 | 现状已完成 | 毕设还需投入 |
|---|---|---|
| 功能开发 | ~85% | 完善路线中的 6 项功能补强（约 3~4 周） |
| 缺陷修复 | P0 级已识别未修 | M1+M2 全部（约 2~3 周） |
| 测试与实验 | 接近 0 | 单测/功能测试/压测/AI 对比实验（约 2~3 周） |
| 论文文档 | 素材零散 | 七件套文档 + 论文正文（约 4~6 周，与上并行） |
| 演示环境 | 本地/局域网可用 | 稳定演示环境（域名可选）（约 2~3 天） |

**合计**：按边做边写、每周 15~20 小时，约 **12~16 周**（一个学期）可到达送审状态。若只剩 8 周，砍单顺序见完善路线 §5。

## 4. 创新点论证（决定论文上限的部分）

### 4.1 选题名称建议（差异化第一步）

避免「二手交易平台的设计与实现」这类烂大街题名，建议：

1. 《基于多模态大模型的二手交易平台智能发布系统设计与实现》
2. 《面向校园场景的 C2C 循环交易平台设计与实现——基于 AI 估价与低碳量化》
3. 《基于规则引擎降级策略的 AI 辅助发布系统设计与实现》（偏方法）

### 4.2 可成文的三个创新/特色点

| 创新点 | 论文写法 | 需要的实验/数据 |
|---|---|---|
| ① AI 智能发布（多模态识别 + 规则引擎降级 + 历史成交价修正） | 「混合架构」：模型输出经历史均价约束修正，无 Key 时规则引擎兜底保证可用性；可与纯大模型方案做**对比** | AI 建议价 vs 实际成交价偏差统计（30~50 样本）；降级可用性验证 |
| ② 低碳循环看板（减排量/省钱额可量化） | 平台社会价值建模：分类减排系数 + 成交数据聚合 | 真实成交数据的看板截图；系数口径说明与敏感性分析 |
| ③ 担保交易与三级权限安全体系 | 资金安全设计：原子扣减、托管状态机、越权防护 | 并发扣款正确性测试（多线程用例）；越权用例测试表 |

### 4.3 与竞赛的复用

《参赛改造规划.md》中挑战杯申报材料（创新点 B3 表、社科选题）与毕设论文素材高度重叠，**一次实验、两处使用**。

## 5. 主要风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 评审认为"电商系统没新意" | 高 | 选题名称+摘要突出 AI 与低碳；论文第 1 章用数据说明二手循环经济背景 |
| 被问到支付为什么是模拟的 | 高 | 用支付宝沙箱补齐真实支付（无需商户资质），论文明确写"沙箱环境验证支付链路" |
| 状态机死代码被追问 | 中 | 送审前完成 M2；状态图只画整理后的真实流转 |
| 伪微服务架构被识破 | 中 | 架构图按单体+模块画；或先完成 M3.3 更名 |
| 实验数据不足 | 中 | 完善路线安排了两组必做实验（并发扣款、AI 估价偏差） |
| 演示现场翻车 | 中 | 演示脚本预录视频兜底 + 本地双备份（后端 jar + 数据库快照） |
| 创新点查重/撞题 | 低 | AI+低碳+担保交易三者组合在二手平台语境下组合度较低 |

## 6. 最终结论

- **可行性结论：可行。** 功能规模、技术栈、业务复杂度均达到甚至超过本科毕设典型水平，AI 与低碳差异化提供了冲出"普通商城毕设"圈层的机会。
- **前置条件（缺一不可）**：
  1. 修复 P0 级安全/正确性问题（S1~S4）——否则实现分受损；
  2. 补齐测试与两组实验数据——否则无论文"验证"章节；
  3. 整理订单状态机——否则设计章节站不住；
  4. 支付走沙箱——否则答辩必被问。
- **具体补齐计划见《毕业设计完善路线.md》**（按 12~16 周排期，含每周任务与论文章节对应关系）。
