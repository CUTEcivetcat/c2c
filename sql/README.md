# SQL 目录说明

> **当前只有一套全量脚本**：历史增量（banner 表、二级密码、三级权限、扩充数据）已全部并入 `init.sql` + `data.sql`，无需再执行任何增量/归档脚本。

## 一、全量脚本（全新环境 / 重灌唯一入口）

| 文件 | 用途 | 用法 |
|---|---|---|
| `init.sql` | **全量建表**：20 张表 + 全部字段（含 `secondary_pwd` 二级密码、`admin_level` 管理员等级、`admin_perms` 权限码、`banner` 轮播图表、`sys_config` 系统运行配置表） | `mysql -uroot -p c2c < init.sql` |
| `data.sql` | **全量演示数据**：8 用户（admin 为总管理员 `admin_level=2`）、30 商品（覆盖教材/英语/笔记本电脑/苹果手机/宿舍用品全部分类）、30 商品图、8 收藏、3 意向、3 轮播图、1 公告、订单/钱包余额，以及 4 项系统默认配置（验证码回显关闭、管理员登录锁定 5 次/15 分钟） | `mysql -uroot -p c2c < data.sql` |

```bash
mysql -uroot -p c2c < init.sql   # ① 建表（会清空重建 c2c 库）
mysql -uroot -p c2c < data.sql   # ② 导入演示数据
```

## 二、更新规范

1. 新增表/字段/数据 → **直接同步进全量脚本**（`init.sql` 加表/字段、`data.sql` 加数据），保证全新部署一步到位，不另立增量文件。
2. 线上已有库需要平滑升级且不方便重灌时 → 临时增量脚本执行完后**并入全量脚本并删除**，避免脚本越积越多、口径混乱。
3. 全量脚本任何修改必须自测通过（建库 → 导数 → 启动后端验证核心页面）后再交付。

## 三、关键数据约定

- 总管理员：`admin`（`role=1` + `admin_level=2` + `admin_perms='*'`）
- 次级管理员：`role=1` 且 `username<>'admin'`（`admin_level=1`，权限码按需配置）
- 审核员：`role=2`（仅用户端审核工作台，不能登录管理端口）
- 演示登录：手机号验证码登录（测试环境验证码回显）或 演示账号统一密码 `ww123456`（含 admin，见 data.sql 头部注释）
